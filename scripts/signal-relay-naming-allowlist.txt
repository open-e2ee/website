# Signal Relay naming allowlist for scripts/check-signal-relay-naming.mjs.
#
# Each entry is one bare relay identifier that remains in this repository:
#   <owner> <path> <identifier>
# <owner> is the task in docs/plans/signal-relay-naming-migration-plan.html
# (or the payments plan for PP52) that removes the hit, or the founder
# decision (NM-FD<n>) that keeps the hit as an approved historical constant.
# Remove an entry in the commit that removes its hit. In a pull request the
# guard fails on an entry or directive that the base branch does not hold, so
# this list only shrinks. An NM-FD25 entry is the one exception.
#
# NM-FD25 marks an SDK role name, such as adapters.relay or hosted.relayUrl.
# The ruling sdk-role-names-20261109 in docs/decisions.md keeps these names.
# In this repository an NM-FD25 entry is permitted only in the demo and
# example code and in the tests that check that code.
# tests/signal-relay-naming-scope.test.mjs lists the scope and enforces it.
#
# NM-FD5 keeps the frozen dated Relay terms and limits pages as published.
# They link the pricing plan table by its old id, which now lands at the top
# of /pricing. The live pages link the signal-relay id.
#
# NM-FD11 keeps the attested public release manifest at its URL. The file
# name and release id stay, and the workflow, verifier, and test keep the path
# and id that they attest and check, so the manifest and its attestation still
# verify. The next release manifest takes a signal-relay id.
#
# The guard skips dist/, build/, node_modules/, and the lockfiles itself, and
# .gitignore covers .astro/ and the other generated output, so this file has
# no ignore directives.
