/* The band the homepage gives the demo: its one paragraph of lead, then the
   console. Not `.stack`, whose `align-items: flex-start` would shrink the
   console to its content width instead of letting it take the band.

   The band itself is a flex item of `.container.stack`, so the same
   `flex-start` acts on it from above. Without the stretch, the band sits at
   its content width, and that width changes the moment a run starts and the
   scene fills — the whole console widens under the reader's press. */
/*
 * The demo console: the drawing, a transport under it, and three columns.
 *
 * The columns are the two devices with the relay between them, in that order in
 * the source, so the stacked layout is the source order and needs no `order`
 * property to produce it. Reading down a narrow screen gives A, then the relay,
 * then B — the path the message actually takes.
 *
 * The controls are `.oe-button` from @open-e2ee/design rather than a set defined
 * here. There is nothing about a demo control that differs from a control
 * anywhere else on the site, and a second button style maintained beside the
 * shipped one is the drift this sheet has paid for before.
 */

  display: flex;
  flex-direction: column;
  gap: var(--oe-space-6);
  /* `.stack` starts its children at their content width. Every other band's
     exhibit is a full-width box, and this one has to be too or the scene sets
     its own width from the widest device in it. */
  align-self: stretch;
}

/*

/*
 * The commit graph that closes the page: four commits down a trunk, and the
 * line running on past the last of them.
 *
 * Geometry in local rem rather than the spacing scale. The scale prices reading
 * rhythm — the distance from a heading to its paragraph — and this is a drawing,
 * where a rail has to land on the center of a node to the pixel. The diagram CSS
 * further up works the same way for the same reason.
 */
.commitline {
  --commitline-node: 0.75rem;
  --commitline-rail: 2px;
  --commitline-row: 3.25rem;
  /* Where the words start. The rails keep a gutter to themselves and every word
     sits in one column — the arrangement of `git log --graph`. */
  --commitline-gutter: 3.5rem;
  /*
   * The dwell: how long one step of the sequence takes to arrive, and the
   * spacing between steps. A local constant, never `--oe-duration-*` — those are
   * transition durations and collapse to 0.01ms under reduced motion, which
   * would play the whole sequence inside a single frame.
   */
  --commitline-beat: 0.42s;
}

.commitline-commits {
  list-style: none;
  margin: 0;
  padding: 0;
}

.commitline-commits > li,
.commitline-onward {
  position: relative;
  display: flex;
  align-items: center;
  height: var(--commitline-row);
  padding-left: var(--commitline-gutter);
}

/* The run past the last commit is longer than a row, because a rail that leaves
   the figure has to read as continuing rather than as stopping just below. */
.commitline-onward {
  height: calc(var(--commitline-row) * 1.4);
}

/* A rail segment fills its own row, so consecutive rows draw one unbroken trunk
   with no seam to align. */
.commitline-seg {
  position: absolute;
  top: 0;
  left: calc(var(--commitline-node) / 2 - var(--commitline-rail) / 2);
  width: var(--commitline-rail);
  height: 100%;
  /* `--oe-border` is the color of a container edge and is all but invisible
     against the dark canvas. This is a drawn line and has to carry at reading
     distance. */
  background: var(--oe-muted);
  transform-origin: top;
}

/* The trunk starts at the first commit. A stub above it would draw history this
   graph does not show. */

  top: 50%;
  height: 50%;
}

@media (prefers-reduced-motion: no-preference) {
  /*
   * Armed is the finished drawing taken back to nothing, and only the script
   * applies it. Authoring the empty state in the markup instead would ship a
   * blank band to every reader whose JavaScript never ran.
   *
   * Nothing here animates opacity or color. A rail grows, a dot lands, a word
   * is written out — every step is geometry, and every step is still present in
   * the finished state a reduced-motion reader gets.
   */
  .commitline[data-armed] .commitline-seg {
    transform: scaleY(0);
  }

  .commitline[data-armed] .commitline-node {
    transform: scale(0);
  }

  .commitline[data-armed] .commitline-word {
    clip-path: inset(0 100% 0 0);
  }

    animation: commitline-rail calc(var(--commitline-beat) * 0.9) ease-out both;
    animation-delay: calc(var(--commitline-step) * var(--commitline-beat));
  }

  /* The run past the last commit takes longer, because it is longer. Reusing the
     row duration would send it out of the figure at nearly twice the speed of

/* One column below 48rem, and the graph first in both arrangements. The graph is
   vertical at every width and the mark is square at every width, so the pair
   stacks without either figure being redrawn for the narrow case. */
.commitline-pair {
  display: grid;
  gap: var(--oe-space-6);
  align-items: center;
  margin-bottom: var(--oe-space-4);
}

/* Both columns are sized to their figures rather than sharing the container, and
   the pair is centered in it. A second column taking the whole remainder would
   push the mark near two thirds across a band this wide, which puts a screen's
   worth of air between two figures that are meant to be read as a pair; sizing
   both to their contents keeps them together and leaves the slack outside the
   pair, where centring can split it evenly.

   The graph's column is `max-content` rather than a width picked to fit it: its
   longest row is the one the graph ends on, and a fixed width wraps that row the
   moment the wording changes. Held to the container underneath, so a narrow
   viewport shrinks the column instead of overflowing the band.

   The mark's column is its own `max-width` and not a round number above it. A
   wider track centers the two tracks but not the two drawings: the mark sits at
   the left of its track, so every pixel the track has spare lands on the right
   of the composition and the ink reads off-center by that much. */
@media (min-width: 48rem) {
  .commitline-pair {
    grid-template-columns: minmax(0, max-content) minmax(0, 34rem);
    justify-content: center;
    gap: var(--oe-space-8);
  }
}

/*
 * The field's box, which the script measures to place its lights. The ratio is
 * the composition's own — `FIELD_VIEW_BOX` in `src/lib/starfield-marks.mjs`,
 * asserted against this rule in `tests/site-content.test.mjs`. A box of another
 * shape does not crop the composition, it squashes it, because the marks are
 * laid out from the box rather than drawn into it.
 *
 * The cap is what the horizontal lockup costs. That lockup is 4.7 times wider
 * than it is tall and its symbol is a sixth of its width, so the symbol — and
 * with it the bracket stem the field has to resolve — is set by how wide this
 * box gets. At 20rem the stem fell to 5px and our own mark read as a dotted
 * line beside two solid ones. 34rem still leaves the pair centered inside the
 * band at every width the two columns hold.
 */
.starfield {
  position: relative;
  width: 100%;
  max-width: 34rem;
  aspect-ratio: 100 / 42;
  margin-inline: auto;
  color: var(--oe-muted);
}

  inset: 0;
  width: 100%;
  height: 100%;
}
